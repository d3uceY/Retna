# Palette Recipes

Worked recipes, with the commands actually run and the numbers they printed. Every ratio
below came out of `retna`, not out of a design intuition.

Recipes are ordered by how often they come up. Use them as a starting point; re-measure
whenever you change a color, because the ratios are properties of *pairs*, not of colors.

---

## Recipe 1 — A ramp from a brand color

**Goal:** turn one brand hex into an 11-stop scale that behaves in light and dark themes.

### 1. Read the brand color in OKLCH

```bash
retna convert "#1a73e8" --to oklch
# OKLCH  oklch(0.5737, 0.1946, 257.86)
```

Hue 257.86 is the identity of this ramp. Keep it (or drift it deliberately, warming the dark
end if you want a natural look). Chroma and lightness do the work.

### 2. Walk lightness, taper chroma

Chroma should peak in the middle stops and taper at both ends. A worked example, generated by
converting each stop with `retna convert "oklch(L C 257.86)" --to hex`:

| Stop | OKLCH | Hex | |
| --- | --- | --- | --- |
| 50 | `oklch(0.97 0.020 257.86)` | `#EDF6FF` | page background |
| 100 | `oklch(0.94 0.040 257.86)` | `#DBEDFF` | subtle fill |
| 200 | `oklch(0.88 0.080 257.86)` | `#B7DAFF` | borders on dark, text on dark |
| 300 | `oklch(0.80 0.120 257.86)` | `#8DC0FF` | muted text on dark |
| 400 | `oklch(0.71 0.165 257.86)` | `#5BA1FF` | borders on dark surfaces |
| 500 | `oklch(0.62 0.190 257.86)` | `#3082F6` | brand base, large text on light |
| 600 | `oklch(0.55 0.190 257.86)` | `#146CDD` | **primary button, body text on light** |
| 700 | `oklch(0.48 0.170 257.86)` | `#0958BB` | text on light |
| 800 | `oklch(0.40 0.140 257.86)` | `#074491` | deep accent |
| 900 | `oklch(0.31 0.100 257.86)` | `#092E61` | text on light, dark surfaces |
| 950 | `oklch(0.24 0.070 257.86)` | `#071E40` | darkest surface |

### 3. Verify the pairs you will actually ship

```bash
retna contrast "#0958BB" "#EDF6FF"    # 700 on 50
retna contrast "#FFFFFF" "#146CDD"    # white on the button
retna contrast "#8DC0FF" "#092E61"    # 300 on 900 (dark theme)
```

Measured:

| Pair | Ratio | AA normal | AAA normal |
| --- | --- | --- | --- |
| 700 on 50 — body text, light theme | **6.15:1** | PASS | FAIL |
| 600 on 50 — body text, light theme | 4.56:1 | PASS | FAIL |
| white on 600 — primary button | 4.98:1 | PASS | FAIL |
| white on 500 — brand base as a button | 3.72:1 | **FAIL** | FAIL |
| 300 on 900 — body text, dark theme | **7.06:1** | PASS | PASS |
| 200 on 950 — body text, darkest theme | 11.42:1 | PASS | PASS |
| 900 on 100 — text on subtle fill | 11.16:1 | PASS | PASS |

Two lessons fell straight out of the table:

- **The brand base color is not the button color on light backgrounds.** White on 500 is
  3.72:1 — fine for large text, a failure for a label. Ship white on **600**, or make the
  button label large.
- **Instinct picks borders that fail the 3:1 non-text rule.** `#8DC0FF` (300) on `#EDF6FF`
  (50) measures **1.73:1**; `#0958BB` (700) on `#071E40` (950) measures **2.46:1**. Both are
  invisible to low-vision users. Use the *deeper* stop on light surfaces and the *lighter*
  stop on dark surfaces: 600 on 50 = 4.56:1, 400 on 950 = 6.29:1.

### 4. Confirm nothing clipped

Each stop above converted back to the exact requested L and C, so nothing was clipped. If a
stop comes back with a *different* chroma and hue than you asked for, you asked for chroma
sRGB doesn't have. Lower C and re-convert. Never accept the clipped value silently — after
clipping, the hue is somebody else's decision.

## Recipe 2 — Semantic tokens

Reference tokens are the ramp. Semantic tokens give it meaning. Components use semantic names.

```css
:root {
  /* reference */
  --blue-50: #EDF6FF;  --blue-500: #3082F6;  --blue-600: #146CDD;
  --blue-700: #0958BB; --blue-900: #092E61;  --blue-950: #071E40;
  --gray-50: #FAFAFA;  --gray-100: #F4F4F5;  --gray-500: #71717A;
  --gray-900: #18181B;

  /* semantic */
  --surface: var(--gray-50);
  --surface-raised: #FFFFFF;
  --text: var(--gray-900);
  --text-muted: var(--gray-500);
  --border: #D4D4D8;
  --accent: var(--blue-600);
  --on-accent: #FFFFFF;
  --focus-ring: var(--blue-600);
}
```

Then check the semantic layer, not the raw palette — that is the set that actually ships:

```bash
retna palette contrast --foreground "#18181B" \
  --colors "#FAFAFA,#FFFFFF,#F4F4F5" --min 4.5

retna contrast "#71717A" --against "#FAFAFA,#FFFFFF" --min 4.5
retna contrast "#D4D4D8" --against "#FAFAFA" --min 3     # border: 3:1, not 4.5
retna contrast "#FFFFFF" --against "#146CDD" --min 4.5
```

The muted text is the one that fails most often, and it fails invisibly — `#A1A1AA` on white
looks "subtle", not broken, and measures 2.56:1:

```bash
$ retna contrast "#A1A1AA" "#FFFFFF"
Ratio       2.56:1
AA Normal   FAIL

$ retna fix "#A1A1AA" --background "#FFFFFF" --level AA

Original       #A1A1AA  2.56:1  FAIL
Background     #FFFFFF
Target                  4.50:1

Suggested colors
Color       Ratio   WCAG  Note
──────────  ──────  ────  ───────────────
   #76767E  4.50:1  PASS  smallest change
   #75757E  4.56:1  PASS
```

`#76767E` is barely distinguishable from `#A1A1AA` to most eyes and passes AA. Do not hand-tune
greys by eye — `fix` holds the hue and chroma and only moves OKLab lightness, which is exactly
the axis that controls the ratio.

## Recipe 3 — Dark theme

Don't invert. Re-derive, then re-measure.

- Background becomes a dark neutral, not black: `#09090B` / `#18181B`.
- Text becomes off-white: `#FAFAFA`, not `#FFFFFF`.
- Surfaces step *lighter* with elevation: base `#09090B` → card `#18181B` → input `#27272A`.
- Muted text moves *up* the ramp (in light mode `gray-500`; in dark mode `gray-400`).
- Brand color moves *up and out*: the 500/600 stops are too dark on a dark surface, so use
  300/400 and check that saturation didn't get harsh.

Then run the whole pair list again on the dark surfaces. See
[dark-mode.md](dark-mode.md) for the full token scales and the specific mistakes.

```bash
retna contrast "#A1A1AA" --against "#09090B,#18181B,#27272A" --min 4.5
retna contrast "#FAFAFA" --against "#09090B,#18181B,#27272A" --min 4.5
retna contrast "#5BA1FF" --against "#09090B,#18181B" --min 4.5
retna contrast "#3F3F46" --against "#18181B" --min 3    # dark-mode border
```

Note the third pattern: an accent that was fine on white needs a *lighter* stop on dark. It is
a different token, not a computed inversion.

## Recipe 4 — Text color for an arbitrary surface

Given a surface with no defined ink ramp (a user-chosen color, a photo-derived accent, a
third-party brand color):

```bash
retna readable "#3498db"
#   #000000  6.66:1  PASS
#   #FFFFFF  3.15:1  FAIL

retna readable "#3498db" --best            # one answer
retna readable "#3498db" --candidates "#18181B,#3F3F46,#71717A,#FAFAFA"
```

Prefer `--candidates` when the design has an ink ramp: "use `--text`" beats introducing a new
color. Use plain `readable` (black vs. white) only when nothing else exists.

For a *fixed* text color that must sit on a surface, let `fix` move the color it is given:

```bash
$ retna fix "#FFFFFF" --background "#3082F6" --target 4.5 --suggest 2

Original       #FFFFFF  3.72:1  FAIL
Background     #3082F6
Target                  4.50:1

Suggested colors
Color       Ratio   WCAG  Note
──────────  ──────  ────  ───────────────
   #1D1D1D  4.54:1  PASS  smallest change
   #1C1C1C  4.58:1  PASS
```

White on that blue only reaches 3.72:1, so the readable answer is a near-black label (or a
darker surface stop). `fix` changes the color you hand it: if the surface is fixed by the
brand, hand it the text color; if the text is fixed, hand it the surface color and accept that
the surface moves.

## Recipe 5 — Auditing an existing palette

You don't have to retype hexes. Pull them out of the stylesheet and pipe them in:

```powershell
# PowerShell: every hex in a stylesheet, one per line
(Select-String -Path app.css -Pattern '#[0-9a-fA-F]{3,8}' -AllMatches).Matches.Value |
  Sort-Object -Unique | Set-Content palette.txt

retna palette contrast --foreground "#FFFFFF" --file palette.txt
retna palette contrast --foreground "#18181B" --file palette.txt --min 4.5
```

```bash
# bash
grep -oE '#[0-9a-fA-F]{3,8}' app.css | sort -u > palette.txt
retna palette contrast --foreground "#FFFFFF" --file - < palette.txt
```

`--min` turns an audit into a gate. Build the two lists that matter — "every surface" and
"every text color" — cross them, and let the tool report which pairs fail instead of guessing
which ones to spot-check.

## Recipe 6 — Chart and category palettes

**The N² problem.** WCAG wants 3:1 between adjacent non-text elements. Making *n* chart fills
each hold 3:1 against every other is easy at n=2, hard at n=3, and effectively impossible
beyond that. Don't fight it: put a **border** on every mark and require 3:1 between each fill
and the border color. That's *n* constraints instead of n².

```bash
# each fill against the shared border, not against each other
retna contrast "#3082F6" "#FFFFFF" --min 3
retna contrast "#F59E0B" "#FFFFFF" --min 3
retna contrast "#10B981" "#FFFFFF" --min 3
```

**Separate by lightness as well as hue.** Two colors can look distinct to a trichromat and
collapse in grayscale or under CVD. Compare their `luminance` from `retna inspect --json` — if
two categories sit at nearly the same luminance, that's the pair that will merge.

```bash
retna inspect "#3082F6" --json   # luminance is the last field
```

**Orange↔blue is the accessible pair** — it survives both red-green and yellow-blue
deficiency. Red↔green alone is the classic failure.

**Sequential ramps need a flat perceptual derivative**: even perceptual steps end to end, in
color and in grayscale. Sample every stop with `retna inspect --json` and compare the OKLCH
lightness deltas; a bump means the ramp exaggerates change that isn't in the data.

## Recipe 7 — CI gate

```yaml
# .github/workflows/a11y.yml
- name: Check color contrast
  run: |
    retna contrast "${{ vars.TEXT }}" "${{ vars.SURFACE }}" --min 4.5
    retna palette contrast --foreground "${{ vars.TEXT }}" \
      --colors "${{ vars.SURFACES }}" --min 4.5
```

Exit code is 1 when any pair falls below the minimum, so the step fails the build. Keep the
pair list in a file next to the tokens so the gate and the stylesheet cannot drift apart:

```bash
retna palette contrast --foreground "#18181B" --file checks/text-pairs.txt --min 4.5
```

## Things this tool will not do for you

Stated plainly so you don't invent a workflow around them:

- **No palette generation.** Retna measures and converts; it does not invent colors. You
  choose the hue, the chroma curve, and the intent.
- **No CVD simulation.** It reports the luminance and the ratio, which is enough to catch
  luminance collisions, but it will not show you deuteranopia.
- **No ΔE / color-difference metric.** Compare luminance and OKLCH channels instead.
- **No gamut-membership check.** Out-of-gamut input is clipped on the way in, so the check is
  "convert back and compare with what you asked for" (Recipe 1, step 4).
- **No contrast for text over images or gradients.** Flatten the composite yourself, then
  measure the resulting pair.
